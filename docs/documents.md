# Документы, договор и лицензия, отметки передачи

Документ описывает правила обработки документов карточки взаимодействия (ТЗ §4 ФТ3, §2 п.4), договорных полей продукта (ТЗ §2 п.6, §4 п.1) и отметок передачи материалов, лицензии и документации (ТЗ §2 п.7, п.12).

## Документы

Файл загружается в карантин, проверяется по сигнатуре содержимого и антивирусом ClamAV; скачать и открыть можно только файл со статусом «Проверен: доступен». Допустимые форматы: PNG, JPEG, HEIC/HEIF, PDF, ZIP, GZIP, RAR, DOC, DOCX, XLS, XLSX, до 20 МБ.

### Вид документа

У каждого файла есть вид (`kind`) из фиксированного справочника: договор, лицензионное соглашение, приложение, акт, скан подписанного документа, учебные материалы, документация продукта, рабочая программа, документ о повышении квалификации, иное. Вид выбирается при загрузке (`kind` в multipart-запросе, по умолчанию «Иное») и меняется командой `PATCH /api/attachments/{id}` с `version` сведений о файле; устаревшая версия даёт `409 VERSION_CONFLICT`. Список документов в карточке отбирается по виду. Справочник закреплён в коде (`AttachmentKind`) до согласования с заказчиком.

### Новая версия

«Загрузить новую версию» передаёт `replacesId` прежнего файла. Новый файл получает этап и вид прежнего (вид можно указать явно), номер версии `revision` на единицу больше, прежняя версия остаётся в списке и скачивается. У файла может быть только одна живая замена (в карантине или проверенная); вторая параллельная замена отклоняется с `409 VERSION_CONFLICT`, в PostgreSQL это закреплено частичным уникальным индексом `attachments_live_replacement_key`. Отклонённая антивирусом замена не блокирует новую попытку.

### Удаление ошибочного файла

`POST /api/interactions/{id}/attachments/{attachmentId}/deletion` с `version` карточки, необязательной причиной (до 500 символов) и `Idempotency-Key`. Удалить может автор файла или руководитель команды (`LEADER`) в своей области; другой КАМ получает `403`, файл чужого вуза — `404`. Удаление мягкое: строка получает `deleted_at` и `deleted_by`, объект в хранилище остаётся для аудита, но файл исчезает из карточки и больше не выдаётся ни на скачивание, ни на просмотр (`404`). Команда увеличивает версию карточки и пишет событие истории `ATTACHMENT_DELETED` с именем файла, видом, номером версии, автором и причиной. Файл, выбранный сканом договора или подтверждением передачи, удалить нельзя (`400`), пока его не заменят в форме продукта. После удаления последней версии прежняя снова может получить замену.

### Просмотр без скачивания

`GET /api/attachments/{id}/preview` отдаёт проверенный PDF, PNG или JPEG с `Content-Disposition: inline`, `X-Content-Type-Options: nosniff`, `Content-Security-Policy: default-src 'none'; img-src 'self'; style-src 'unsafe-inline'; object-src 'self'; frame-ancestors 'self'`, `Cross-Origin-Resource-Policy: same-origin` и `Cache-Control: private, no-store`. Кнопка «Просмотреть» открывает файл в новой вкладке браузера по той же сессии. Для остальных форматов просмотр отклоняется с `400`, их можно скачать.

### Фото HEIC с телефона

HEIC и HEIF принимаются, если файл начинается с блока `ftyp` с маркой HEIF (`heic`, `heix`, `hevc`, `hevx`, `heim`, `heis`, `hevm`, `hevs`, `mif1`, `msf1`); AVIF и файлы с чужой сигнатурой отклоняются. Файл проходит антивирус и хранится как есть: преобразование в JPEG требует нативной библиотеки декодирования HEVC, новой тяжёлой зависимости проект не добавляет. В карточке HEIC показывается как обычный файл для скачивания, без просмотра в браузере.

## Договор и лицензия по продукту

Форма «Договор и лицензия» у каждого продукта карточки доступна КАМ и руководителю (`USER`, `LEADER`) в своей области. `PATCH /api/interactions/{id}/product-agreements/{agreementId}` принимает `version` карточки, `Idempotency-Key` и блок `contract`: номер договора (текст до 200 символов, ведущие нули сохраняются, пробелы по краям убираются, пустое значение очищает поле), подписание лицензии (`true`, `false` или `null` — «Не указано»), год окончания лицензии (2000–2100) и `scanAttachmentId` — проверенный файл этого же взаимодействия. Изменение пишет событие `AGREEMENT_UPDATED` с названием продукта и парами «было → стало» по каждому изменённому полю; запрос без фактических изменений возвращает карточку без новой версии. Другие продукты карточки не меняются. Продукт с заполненными договорными данными, сканом или отметками передачи снять с карточки нельзя.

Импорт каталога (`docs/import.md`) по-прежнему может заполнить те же поля; форма и импорт пишут в одну запись `product_agreements`.

## Отметки передачи

Тот же `PATCH` с блоком `transfers` сохраняет три отметки по продукту: материалы (`MATERIALS`), лицензия (`LICENSE`), документация (`DOCUMENTATION`). Каждая отметка — статус `TRANSFERRED` с датой передачи (не позже сегодняшнего дня по Москве) и необязательным подтверждающим файлом или `NOT_TRANSFERRED` без даты и файла. Отсутствующая в списке отметка означает «не отмечено». Список заменяется целиком, поэтому пустой список снимает все отметки.

Статус передачи продукта (`transferStatus`) при сохранении отметок вычисляется: все три переданы — «Передано», часть — «Передано частично», ни одной — «Не передано», отметок нет — статус очищается. Если статус позже изменит импорт, он хранится как есть до следующего сохранения отметок.

## Отчёты и «Моя работа»

- «Портфель взаимодействий» получает колонки «Вендор», «Номер договора», «Подписание лицензии», «Срок лицензии», «Статус передачи», «Передача материалов» (дата передачи материалов). При нескольких продуктах значение пишется по каждому продукту: «Продукт: значение; …». Эти колонки выдаются, только если выбраны явно: запрос с пустым `columns` получает прежние 11 колонок портфеля, как и экран по умолчанию.
- Фильтр `filters.agreement` в «Портфеле» и «Событиях»: вендоры, подписание лицензии (`false` — не подписана или не указано), «лицензия истекает до» (год включительно) и «не передано» по видам отметок (соглашение без отметок со статусом импорта «Передано» считается переданным полностью; другие статусы импорта вид передачи не называют, и такое соглашение остаётся в отборе). Все условия проверяются на одном и том же продукте взаимодействия, при выбранных `productIds` — только на них. Для «Востребованности программ» фильтр отклоняется с `400`. Список вендоров — `GET /api/report-filters/vendors`. Подробно — [reports.md](reports.md).
- Выборка вузов по продукту с датой последней передачи материалов: «Портфель» с фильтром «ИТ-продукты» и колонкой «Передача материалов».
- «Моя работа»: отбор «Лицензия истекает» (`licenseExpiresBy` в `GET /api/interactions`) — взаимодействия, у которых хотя бы у одного продукта год окончания лицензии не позже выбранного.

## Ограничения

- Срок лицензии хранится годом, как в поле ТЗ «Срок действия лицензии (год)»; дата окончания с точностью до дня не ведётся.
- Словари «Подписание лицензии» и «Статус по передаче» остаются открытым вопросом; в CRM подписание — да/нет/не указано, статус передачи вычисляется по отметкам.
- Версия переданных материалов — номер версии прикреплённого файла; отдельного поля версии материалов нет.
- Удалённые файлы остаются в хранилище; срок их хранения и окончательное удаление определяются политикой ИБ заказчика.
