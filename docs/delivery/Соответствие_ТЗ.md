# Соответствие ТЗ

Таблица сверяет требования ТЗ с фактическим кодом репозитория и покрывающими его автотестами. Источники: исходное ТЗ, код `backend/src/main/java/ru/rtk/crm/**` и `frontend/src/**`.

Статусы: **выполнено и проверено** (есть живая проверка на стенде или воспроизводимая внешняя проверка), **выполнено, не проверено** (код и автотесты есть, живой проверки на поднятом стенде не было), **частично** (часть требования закрыта, часть — нет, либо требование выполняется с оговоркой или при определённом условии), **не выполнено**.

Доступа к API сайта заказчика и его LMS-стендам нет, поэтому критерий приёмки интеграций сайта и приёма оплат — соответствие контракту и работа на заглушке, а не доступ к настоящей системе (`docs/integrations/Заглушки.md`). FR-10 и источник «Веб-сайт» ниже оценены по этому критерию, как и FR-09/Moodle.

## 9. Модуль «Слушатели»

Каталоги от организатора (Вендоры.xlsx, Данные оплат.json, Загрузка пользователей.xlsx) использованы для проектирования формата и синтетических тестовых данных; данные людей из этих файлов в код, тесты и документы не копировались. Ничего из модуля не проверялось на живом стенде (PostgreSQL, Keycloak, браузер); все перечисленные ниже пункты покрыты автотестами backend.

| Требование | Статус | Как выполнено | Что осталось |
|---|---|---|---|
| Единая точка входа ПДн — флаг «Оператор зачисления»; служебный актор для приёма данных с сайта | выполнено, не проверено | доступ к модулю проверяется по флагу на каждом запросе; оплаты, пришедшие синхронизацией сайта, записываются от имени служебного актора «Система» | живая проверка на стенде |
| Модель данных (потоки, анкеты, зачисления) | выполнено, не проверено | таблицы `enrolment_streams`, `learners`, `learner_enrolments`; тесты хранения на H2 в режиме PostgreSQL | применение миграций по возрастанию на живом PostgreSQL |
| Шифрование AES-256-GCM по полям, AAD, отпечатки (email/телефон/СНИЛС/ФИО/фамилия) | выполнено, не проверено | каждое поле анкеты шифруется отдельно; отпечатки HMAC для поиска без расшифровки | живая проверка на PostgreSQL (дамп БД без ключа не раскрывает значений) |
| Доступ: только флаг видит анкеты; ADMIN — только функции субъекта ПДн | выполнено, не проверено | `404` при выключенном модуле, `403` без флага (включая ADMIN) | живая проверка |
