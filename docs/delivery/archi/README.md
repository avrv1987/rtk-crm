# Модель архитектуры в Archi

Файл `rtk-crm.archimate` — редактируемая модель CRM ИТ Школы РТК в формате инструмента Archi (ТЗ, раздел 6, п. 7: «описание функциональной и компонентной архитектуры в Archi»). Модель соответствует текущему коду репозитория, включая вендоров, оплаты, модуль «Слушатели» (хранилище, процессы, API и экран «Зачисление») и пакет ИБ.

## Как открыть

1. Установить Archi 4.9 или новее с официального сайта <https://www.archimatetool.com/download/> (бесплатно, Windows, macOS, Linux).
2. В Archi выбрать **File → Open…** и указать файл `docs/delivery/archi/rtk-crm.archimate`.
3. В дереве **Models** раскрыть модель «CRM ИТ Школы РТК», затем папку **Views** и дважды щёлкнуть нужное представление.

Изображение для документа: открыть представление, затем **File → Export → View As Image…** (PNG или SVG). Полный HTML-отчёт по модели: **File → Report → HTML…**.

## Представления

| Представление | Что показывает |
|---|---|
| Функциональная архитектура | Бизнес-роли (КАМ, руководитель, администратор платформы), процесс взаимодействия с вузом из 14 шагов ТЗ (раздел 2) с необязательной корректировкой документов, процессы назначения КАМ, отчётности и сопровождения CRM, прикладные сервисы и связи «обслуживает», «назначение», «реализация». Роль «Руководство» (MANAGEMENT) и дополнительные модули — на представлении «Соглашения, вендоры, «Слушатели» и публикация за прокси» ниже, здесь не продублированы |
| Компонентная архитектура | React SPA, nginx, Spring Boot API и его модули по пакетам `ru.rtk.crm.*` (access, catalog, catalogimport, interaction, attachment, report, security, web, bootstrap, source), PostgreSQL, Keycloak, ClamAV, Moodle, сайт Laravel; интерфейсы REST `/api`, Swagger UI, OIDC, JDBC, clamd, Moodle Web Services, JSON сайта; Linux-сервер с Docker Engine и Compose |
| Развёртывание | Контейнеры `compose.yaml` (web, backend, postgres, keycloak — профиль по умолчанию; clamav — профиль `security`; backend-bootstrap — профиль `demo`), их образы, конфигурация и тома; отличия `compose.prod.yaml`; отдельный профиль `infra/moodle/compose.yaml` для локального Moodle |
| Соглашения, вендоры, «Слушатели» и публикация за прокси | Пакеты `agreement`, `audit`, `privacy`, `training`, `enrolment` и их прикладные сервисы (соглашения и план мероприятий, документы и договор, журнал администратора и безопасности, субъект ПДн, сроки хранения, циклы работы и обучение преподавателей, вендоры и контакты вендоров, модуль «Слушатели»); роль «Руководство»; общий edge Caddy, `compose.edge.yaml`, Moodle на отдельном имени. Показаны не все связи первых трёх представлений — только то, что относится к дополнениям |

У модулей API в свойствах (вкладка **Properties**) указан каталог исходного кода. Пояснения к элементам — во вкладке **Documentation**.

## Соответствие коду

Представление «Соглашения, вендоры, «Слушатели» и публикация за прокси» и прикладной сервис «Модуль «Слушатели»: анкеты, шифрование, файл для LMS» сверены с кодом `ru.rtk.crm.enrolment`: анкета из 30 полей, шифрование AES-256-GCM с AAD, поиск по HMAC-отпечаткам, поток = курс + номер, файл для LMS из анкет потока, журнал `LEARNER` и доступ по флагу «Оператор зачисления» совпадают с моделью. Пакет ИБ (`docs/delivery/security/`) архитектурных элементов не добавляет: это только документы.

## Как проверен файл

Archi на рабочем месте разработки не установлен, поэтому открытие в самом Archi не проверялось. Структуру файла проверяет скрипт на Python 3.13 (только стандартная библиотека). Он проверяет:

- XML разбирается без ошибок;
- идентификаторы во всём файле уникальны;
- у каждой связи источник и цель ссылаются на существующий элемент, а тип связи входит в перечень ArchiMate 3.1 (Composition, Aggregation, Assignment, Realization, Serving, Access, Influence, Triggering, Flow, Specialization, Association, Junction);
- каждый объект и каждая линия на диаграммах ссылаются на существующий элемент или существующую связь.

Скрипт не проверяет полную таблицу допустимых пар «тип источника — тип связи — тип цели» (она зашита в самом инструменте Archi, `com.archimatetool.model/model/relationships.xml`) и не проверяет, что вложенные объекты диаграмм помещаются в границы родителя — эту проверку без Archi воспроизвести нечем.

Модель нужно один раз открыть в Archi и сохранить: Archi при этом обновит номер версии формата, разложит представления по сетке и покажет возможные замечания в панели проверки модели (Validator).
