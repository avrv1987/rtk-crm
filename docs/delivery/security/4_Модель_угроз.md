# 4. Модель угроз (сокращённая)

Структура следует Методике оценки угроз безопасности информации (ФСТЭК России, 5 февраля 2021 г.): негативные последствия → объекты воздействия → нарушители и их возможности → способы реализации → актуальные угрозы. Это сокращённая рабочая модель для обоснования технических мер продукта. Полную модель угроз с привязкой к банку данных угроз ФСТЭК (bdu.fstec.ru) и к инфраструктуре заказчика составляет оператор или привлечённый специалист по защите информации. Модель включает угрозы Т19–Т31 и объекты воздействия модуля «Слушатели» (раздел 4.2, 4.4).

## 4.1. Негативные последствия

| Вид ущерба | Последствия для CRM |
|---|---|
| У1 — ущерб физическому лицу | разглашение контактов представителей вузов и вендоров (ФИО, почта, телефон, должность) и сведений о сотрудниках; использование этих данных для спама, фишинга, социальной инженерии. Для анкеты слушателя (паспорт, СНИЛС, адрес, дата рождения) вред выше: эти данные пригодны для мошенничества от имени человека, а не только для нежелательных контактов |
| У2 — ущерб юридическому лицу | утрата или искажение истории работы с вузами, договорных сведений и файлов; срыв работы КАМ; неверные отчёты для руководства; нарушение требований 152-ФЗ и связанные с ним санкции; ущерб деловой репутации |

Ущерб государству (У3) для CRM не рассматривается: система не обрабатывает государственную тайну и не управляет значимыми объектами.

## 4.2. Объекты воздействия

| Объект | Компонент (см. модель Archi, представление «Развёртывание») |

| Файлы вложений | том `attachments-data` |
| Файлы отчётов | том `reports-data` (`/var/lib/rtk-crm/reports` в контейнере `backend`) |
| Антивирусная проверка | контейнер `clamav`, протокол clamd |
| Секреты стенда | `.env.local`, `.demo-identities.yml` на сервере |
| Резервные копии | каталог, заданный администратором при запуске `scripts/backup.sh` |
| Сервер и Docker | Linux-хост, Docker Engine |
| Каналы интеграции с Moodle и сайтом | описаны в `docs/integrations.md` |
| Модуль «Слушатели»: таблицы `learners`, `learner_enrolments`, `enrolment_streams`, раздел «Зачисление» | БД CRM в контейнере `postgres`, `backend` (`ru.rtk.crm.enrolment`) |
| Ключи шифрования анкет и отпечатков | окружение контейнера `backend` (`APP_ENROLMENT_KEYS_*`, `APP_ENROLMENT_FINGERPRINT_KEY`), `.env.local` на сервере |
| Файл «Загрузка пользователей» | компьютер оператора зачисления, далее — LMS (файл на сервере не хранится) |

## 4.3. Нарушители

Уровни возможностей — по Методике: Н1 — базовые, Н2 — базовые повышенные, Н3 — средние, Н4 — высокие.

| Вид нарушителя | Внешний / внутренний | Уровень | Актуален | Цель |
|---|---|---|---|---|
| Отдельные физические лица (хакеры) | внешний | Н1–Н2 | да, если стенд доступен из интернета | доступ к данным, использование сервера |
| Преступные группы | внешний | Н2 | да, при публикации в интернете | кража данных, вымогательство |
| Конкурирующие организации | внешний | Н2 | условно: интерес к базе контактов вузов | получение базы контактов |
| Авторизованные пользователи (КАМ, руководители) | внутренний | Н1 | да | доступ к вузам чужой команды или другого КАМ, выгрузка лишних данных |
| Бывшие (уволенные) работники | внешний с прежними знаниями | Н1 | да | вход под старой учётной записью |
| Системные администраторы и администраторы безопасности | внутренний | Н2 | да, как риск ошибки и злоупотребления | чтение или изменение данных в обход приложения |
| Разработчики и поставщики программных средств, образов контейнеров | внешний | Н2–Н3 | да, как риск уязвимости в сторонних компонентах | внедрение уязвимости через зависимость или образ |
| Специальные службы иностранных государств, террористические группировки | внешний | Н3–Н4 | нет: состав данных CRM не соответствует их целям | — |

Нарушители уровня Н3–Н4 с возможностью создавать недокументированные возможности в системном и прикладном ПО не рассматриваются; поэтому предлагается 3-й тип угроз (раздел 2.2).

## 4.4. Актуальные угрозы и сценарии

Меры перечислены кратко; подробное сопоставление с группами мер — раздел 5.

| № | Угроза и сценарий | Нарушитель | Объект | Основные меры в продукте | Остаточный риск |
|---|---|---|---|---|---|
| Т1 | КАМ подставляет в запрос идентификатор чужого вуза, взаимодействия, файла или отчёта | авторизованный пользователь | API | область данных проверяется в SQL-запросе к данным (`OrganizationRepository.visibilityScope`, `findVisibleById`); чужой объект — `404`, действие без права — `403`; отчёт и его файл выдаются только владельцу | низкий |

| Т3 | Кража cookie сессии, перехват трафика | хакер | сессия, канал связи | cookie `SESSION` с `HttpOnly` и `SameSite=Lax`, `Secure` в публикационном варианте; TLS 1.2/1.3 на nginx; токены OIDC в браузер не передаются | демо-вариант работает по HTTP |
| Т4 | Подделка межсайтового запроса (CSRF) | хакер | API | каждый изменяющий запрос требует заголовок `X-CSRF-TOKEN` | низкий |
| Т5 | Внедрение сценария в интерфейс через текст комментария или название | авторизованный пользователь, хакер | SPA | React экранирует выводимый текст; в коде интерфейса нет вставки HTML из данных; заголовок Content-Security-Policy задан на уровне nginx (раздел 5) | низкий |
| Т6 | Загрузка вредоносного файла под видом документа | авторизованный пользователь, хакер | вложения, импорт | проверка расширения и сигнатуры содержимого для 10 форматов ТЗ и HEIC/HEIF (блок `ftyp` с маркой HEIF, AVIF отклоняется); лимит 20 МБ; карантин; проверка ClamAV; скачать можно только файл со статусом «Проверен»; файл хранится под случайным ключом, не под именем пользователя; при скачивании — `X-Content-Type-Options: nosniff` | антивирус находит только известные угрозы |
| Т7 | Формула в тексте, которая выполнится при открытии выгрузки в Excel | авторизованный пользователь | отчёты XLS/XLSX | текст, начинающийся с `=`, `+`, `-`, `@`, записывается как текст (`ExcelReportWriter`) | низкий |
| Т8 | Перегрузка сервера массовыми отчётами или большими файлами | авторизованный пользователь, хакер | backend | пул построения отчётов — 10 заданий и очередь 40, при переполнении `503`; пределы строк отчёта; пределы размера загрузки на nginx и в backend; пределы импорта 5 МиБ и 5 000 строк | нет ограничения частоты запросов на пользователя; защита от DDoS — на стороне сети оператора |
| Т9 | Сохранение доступа после увольнения или смены обязанностей | бывший работник | API | блокировка профиля CRM действует со следующего запроса; файлы отчётов, заказанные до смены прав, не выдаются (`access_revision`, ответ `410`) | отключение только в Keycloak не завершает уже открытую сессию CRM до её истечения (30 минут бездействия): увольняемого нужно блокировать в CRM |
| Т10 | Утечка секретов из репозитория, логов, URL | разработчик, администратор | `.env.local`, журналы | секреты создаются скриптом и хранятся в `.env.local` с правами 600, файл исключён из git; в ответах API нет stack trace и секретов; журнал содержит только `requestId` запроса | секреты видны администратору Docker в окружении контейнеров |

| Т15 | Потеря данных при сбое или ошибке | — | БД, тома | транзакции, проверка версий (`409`), повтор команд без дублей; резервное копирование и восстановление (`scripts/backup.sh`, `scripts/restore.sh`) | копирование по расписанию не настроено; политика автоматического перезапуска контейнеров в `compose.yaml` не задана |
