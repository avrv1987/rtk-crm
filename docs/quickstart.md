# Быстрый запуск: адреса, учётные записи, сборка

Как поднять систему — в [README](../README.md) и [deploy.md](deploy.md). Ниже то, что нужно после запуска.

## Адреса

| Что | Демо-стенд |
|---|---|
| Приложение | `http://rtk.localhost:8081` или `http://localhost:8081` |
| Swagger UI | `http://rtk.localhost:8081/swagger-ui/index.html` |
| OpenAPI | `http://rtk.localhost:8081/openapi.yaml` |
| Keycloak, realm `rtk-crm` | `http://rtk.localhost:8081/idp/realms/rtk-crm/account` |
| Консоль Keycloak | `http://rtk.localhost:8081/idp/admin/`, учётная запись `KEYCLOAK_ADMIN_USERNAME`; в публикационном варианте закрыта |
| Демо-Moodle | `http://localhost:8082`, администратор Moodle — `MOODLE_ADMIN_USERNAME` и `MOODLE_ADMIN_PASSWORD` из `infra/moodle/.env.local`; для жюри — `crm-jury` с паролем `MOODLE_JURY_PASSWORD` оттуда же (только просмотр); в публикационном варианте — отдельное имя `MOODLE_PUBLIC_HOST` за тем же TLS, только на время показа ([deploy.md](deploy.md#moodle-для-жюри)) |

В публикационном варианте вместо `http://rtk.localhost:8081` используется `PUBLIC_ORIGIN`.

## Демо-учётные записи

Пароль у всех один — значение `DEMO_USER_PASSWORD` из `.env.local`. Его не публикуют и не переносят в issue, логи и git. Перед показом посторонним `scripts/secure-demo-accounts.sh` выдаёт оставленным учёткам индивидуальные пароли (файл `.demo-accounts.local`) и отключает остальные; повторный bootstrap это не отменяет ([deploy.md](deploy.md#демо-пользователи-на-публикуемом-стенде)).

| Логин | Роль CRM | Область данных |
|---|---|---|

## Сборка без Docker

Backend (JDK 21; Maven 3.9.16 скачивается Maven Wrapper):

```bash
cd backend
./mvnw test
./mvnw package -Dmaven.test.skip=true
```

Тесты backend без JDK на хосте: `docker build --target test backend`.

Frontend (Node 24.18+ и npm 12.0.2 по `frontend/package.json`); типы API генерируются из `backend/src/main/resources/static/openapi.yaml`:

```bash
cd frontend
npm ci
npm run build
```

Результат — `backend/target/rtk-crm-backend-0.1.0-SNAPSHOT.jar` и `frontend/dist/`. Для запуска jar нужны PostgreSQL, Keycloak и ClamAV; параметры подключения передаются теми же переменными, что в `compose.yaml` (`SPRING_DATASOURCE_*`, `APP_OIDC_*`, `APP_ATTACHMENTS_*`, профиль `oidc`).
