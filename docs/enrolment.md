# Слушатели: оплаты, анкета, файл LMS, шифрование

Модуль «Слушатели» (ТЗ §6.7) хранит анкеты слушателей открытых курсов, принимает оплаченные заявки, формирует и читает файл «Загрузка пользователей» для LMS и шифрует все поля анкеты. Код — пакет `backend/src/main/java/ru/rtk/crm/enrolment`, экран — `frontend/src/features/enrolment`.

Данные людей из файлов организатора в код, тесты и этот документ не переносятся. Тесты используют вымышленные ФИО, адреса `example.test` и СНИЛС с рассчитанным контрольным числом.

| Класс | Назначение |
|---|---|
| `PaidOrderParser` | разбор массива оплат: файл оператора и ответ сайта |
| `LearnerProfile`, `LearnerField` | анкета из 30 полей шаблона «Загрузка пользователей» |
| `LearnerRules` | нормализация и проверки полей анкеты |
| `LmsRosterWorkbookWriter` | формирование XLSX «Загрузка пользователей» |
| `LearnerWorkbookReader` | чтение заполненного шаблона с протоколом ошибок |
| `LearnerDataCipher`, `EnrolmentProperties` | шифрование полей AES-256-GCM и отпечатки HMAC-SHA256 |
| `LearnerRepository`, `EnrolmentRepository` | таблицы `learners`, `enrolment_streams`, `learner_enrolments` |
| `LearnerService` | хранение анкеты: шифрование, отпечатки, правка с версией, анкета с масками, раскрытие групп, журнал |
| `LearnerFieldGroup` | группы полей анкеты и маски |

| `LearnerPrivacyService` | слушатели в функциях субъекта ПДн, обезличивание по сроку, счётчики для администратора |
| `PaidOrderEnrolment` | приём оплаты в модуль в транзакции записи `paid_order`: поток, слушатель, зачисление |
| `EnrolmentStreamService`, `EnrolmentLearnerService` | потоки и слушатели потока, поиск, анкета, правка, перенос зачислений, история |
| `QuestionnaireImportService` | предпросмотр и применение заполненного шаблона |

| `EnrolmentAccess`, `EnrolmentCommands` | проверка модуля и флага в каждом запросе; ключ повтора команд раздела |

Разбор оплат лежит в пакете `enrolment`, а не `source`: им пользуются и загрузка файла оператором, и адаптер сайта. Результат разбора — публичные записи `PaidOrderBatch`, `PaidOrder`, `PaidOrderIssue`; конвейер источников регистрирует из них записи `paid_order` (`docs/integrations.md`, раздел «Оплаченные заявки»).

Загрузка файла оператором: `POST /api/enrolment/paid-orders` (`EnrolmentApiController`, `PaidOrderUploadService`). Доступ проверяет `EnrolmentAccess` при каждом запросе. Пока модуль выключен (`app.modules.enrolment.enabled=false`), метод отвечает `404` всем (`ModuleDisabledException`, перехватчик `ModuleGate`), раздела «Зачисление» нет, а `/api/me` отдаёт `enrolmentOperator: false` и профилю с флагом; синхронизация сайта оплаты не принимает вовсе (запуск завершается с пометкой «модуль выключен», записи `paid_order` не создаются). Во включённом модуле профиль без флага «Оператор зачисления» получает `403` (`EnrolmentAccessDeniedException`). Файл разбирается и передаётся в `SourceSyncService.uploadPaidOrders`: в `source_records` попадают только номер, курс и поток, а ФИО, телефон и email той же транзакцией уходят в зашифрованную анкету (раздел «Приём оплат в модуль»).

## Разбор оплат

Вход — JSON-массив в формате файла организатора «Данные оплат.json». Ответ сайта в том же формате разбирается тем же методом.

| Правило | Значение |
|---|---|
| Размер | до 5 МиБ и до 10 000 элементов. Иначе ошибка файла, ни одна запись не принимается |
| Корень | только массив. Объект, пустой файл и некорректный JSON — ошибка файла |
| `null` | пропускается; увеличивается счётчик пустых элементов, в протокол пишется «Пустой элемент пропущен» |
| Не объект | ошибка элемента |
| Лишние ключи | не читаются |

| Ключ | Обязателен | Длина | Нормализация |
|---|---|---|---|
| Номер заявки | да | 100 | края и повторные пробелы. Непрозрачный идентификатор: дата из номера не извлекается. Номер вне шаблона `ORD-<цифры>-<заглавные латинские буквы и цифры>` даёт предупреждение, запись принимается |
| Курс | да | 300 | края и повторные пробелы |
| Фамилия, Имя | да, но без них запись принимается с предупреждением | 100 | края и повторные пробелы |
| Отчество | нет | 100 | края и повторные пробелы |
| Телефон | да, но неверный телефон — предупреждение, поле не сохраняется | 50 | `+7XXXXXXXXXX` (см. ниже) |
| Email | да, но неверный email — предупреждение, поле не сохраняется | 254 | края; для показа хранится как введён, ключ сравнения — нижний регистр |
| Номер потока | да | — | целое JSON-число от 1; строка `"2"` и `1.5` — ошибка. Поток — курс плюс номер внутри курса |

Строковые поля принимают строку или целое число. Пробелы — любые пробельные символы Unicode, включая неразрывный пробел.

Протокол содержит порядковый номер элемента в массиве (с 1), имя поля, текст и признак `warning`. Ошибка (`warning = false`) означает, что запись не принята: так бывает только из-за номера заявки, курса и номера потока. Предупреждение (`warning = true`) — номер заявки вне шаблона или непрошедшие проверку фамилия, имя, отчество, телефон и email: запись принимается, а такое поле в `PaidOrder` остаётся `null` и в текст добавляется «; поле не сохранено». Значения полей в текст не попадают: «Телефон должен содержать 10 цифр после +7 или 8; поле не сохранено», а не сам номер.

`PaidOrderBatch` кроме записей и протокола считает элементы массива (`elements`), пустые (`emptyElements`) и повторы с тем же содержимым (`duplicates`); `received()` — непустые элементы, `rejected()` — непустые элементы без принятой записи, кроме повторов.

Повтор номера заявки в одном файле. Если все записи с этим номером совпадают целиком, принимается первая, остальные попадают в протокол как «Повтор заявки с тем же содержимым пропущен». Если записи различаются, не принимается ни одна, у каждой ошибка «Номер заявки повторяется в файле с разным содержимым».

Версия записи — SHA-256 от JSON-массива `[курс, номер потока]` после нормализации (`CommandFingerprint`). Номер заявки — ключ записи, поэтому в версию не входит. ФИО, телефон и email в версию тоже не входят: в конвейер источников они не передаются. Та же версия при повторной загрузке заявки с тем же номером означает «без изменений», другая — изменились курс или поток.

## Приём оплат в модуль

Каждая оплата файла оператора и ответа сайта-массива проходит `SiteRecordApplier.applyPaidOrder`: запись `paid_order` и шаг модуля `PaidOrderEnrolment.accept` выполняются в одной транзакции. Сбой шага модуля откатывает и запись: она получает FAILED с причиной без значений и применяется при следующей загрузке. Пока модуль выключен, шаг не выполняется и ФИО, телефон и email отбрасываются.

| Что | Как |
|---|---|
| Когда выполняется | для новых и изменённых записей, для «Пропущено» (та же версия) и для «Требует сопоставления». Поэтому повторная загрузка достраивает зачисления, которых не было (модуль был выключен, запись пришла до пакета), а оплата курса без программы зачисляется сразу: программа потока появится, когда администратор сопоставит курс. Запись с ошибкой (FAILED) в модуль не идёт |
| Поток | курс + номер (`enrolment_streams`): ключ курса — тот же, что у PROGRAM-сопоставления (`SiteRecord.programKey`), название — из первой оплаты |
| Слушатель | если зачисление по этой заявке уже есть — его слушатель. Иначе кандидаты по отпечатку email или телефона, из них — активный (`ACTIVE`) с теми же фамилией и именем; отчество сравнивается, только если оно есть и в оплате, и в анкете. Иначе создаётся новый слушатель. Анкеты с ограниченной обработкой новыми оплатами не находятся: для такой оплаты создаётся новая анкета, а существующая не меняется |
| Зачисление | одно на слушателя в потоке со ссылкой на `source_record`. Оплата слушателя в потоке, где он уже зачислен, — «повторная заявка в потоке»: заявка учтена в спросе, второго зачисления нет |
| Смена курса или потока | зачисление по заявке переходит в новый поток, отметки выгрузки и передачи в LMS снимаются; если в новом потоке слушатель уже зачислен, зачисление по этой заявке удаляется. Если зачисление уже выгружалось для LMS, протокол предупреждает: исключить слушателя из прежнего потока в LMS вручную |
| Данные оплаты | заполняют только пустые фамилию, имя, отчество, телефон и email (событие `LEARNER_CHANGED` с кодами полей). Если телефон или email оплаты отличаются от анкеты, анкета не перезаписывается, протокол считает «контакты отличаются» |
| Автор | загрузка файла — оператор (`learners.created_by`, события `LEARNER_CHANGED`); синхронизация сайта — служебный актор «Система» (`created_by` NULL) |
| Протокол | `PaidOrderUpload.learners`: новых слушателей, найдено, зачислений, повторных заявок в потоке, перенесено в другой поток, из них после выгрузки в LMS, контакты отличаются. Журнал: `PAID_ORDERS_UPLOADED` (загрузка файла, автор — оператор) и `LEARNERS_SYNCED` (синхронизация сайта, автор «Система»); тип объекта `SYNC_RUN`, в подробностях — только числа |

## Анкета слушателя

Анкета — запись `LearnerProfile` из 30 полей в порядке колонок шаблона. Заголовки совпадают с шаблоном организатора байт в байт, включая пропущенные открывающие скобки. Все 30 полей хранятся зашифрованными, каждое отдельно (раздел «Хранение анкет»): дамп БД без ключа не раскрывает ни одного значения, включая ФИО и контакты. Код поля — имя константы `LearnerField`; им подписаны значения в БД, коды в журнале и ошибки полей. Столбец «Группа» — группа маскирования (раздел «Журнал и маскирование»).

|---|---|---|---|---|---|

| C | Отчествопри наличии) | `MIDDLE_NAME` | строка | | `MAIN`, без маски |
| D | Номер телефона | `PHONE` | строка | обязательно; `+7XXXXXXXXXX` | `MAIN`, частично |

Справочник образования, точные строки: «Без образования», «Основное общее образование - 9 классов», «Среднее общее образование - 11 классов», «Среднее профессиональное образование», «Высшее образование – бакалавриат», «Высшее образование – специалитет, магистратура», «Высшее образование – подготовка кадров высшей квалификации». В первых двух дефис (U+002D), в трёх последних короткое тире (U+2013), как у организатора.

Серия, номер, кем выдан, дата выдачи и код подразделения паспорта заполняются вместе или не заполняются: при частично заполненном паспорте ошибка «Паспорт заполняется целиком» стоит у каждого пустого поля паспорта. Слушатель младше 18 лет — ошибка «обработка данных несовершеннолетних не предусмотрена». ФИО, ФИО в дательном падеже и фамилия в дипломе — до 100 символов: буквы, пробел, дефис, апостроф, точка; регион, населённый пункт и улица — до 200 символов, дом и квартира — до 20; номер, серия и регистрационный номер диплома — до 50 символов: буквы, цифры, пробел, дефис.

Фамилия, имя, телефон и email обязательны для файла LMS (колонки A, B, D, E): они приходят из оплаты, остальное оператор дозаполняет постепенно. Их отсутствие не мешает править другие поля анкеты, но очистить их правкой нельзя. Полнота анкеты («Заполнено X из Y», «Анкета заполнена») считается по `learners.missing_fields` без расшифровки: по всем полям, кроме отчества, квартиры и отчества в дательном падеже у слушателя без отчества.

### Нормализация

| Поле | Правило |
|---|---|
| Строки | края и повторные пробелы (включая неразрывные); пустая строка — пустое поле |
| Телефон | допустимы цифры, пробелы, скобки, дефисы и ведущий `+`. 11 цифр с первой 7, или с первой 8 без `+`, — `+7` и последние 10; 10 цифр без `+` — `+7` и они. Первая из 10 цифр — от 3 до 9: коды зон и DEF-коды России не начинаются с 0, 1 и 2. Иначе значение остаётся как введено и не проходит проверку: `+8 …`, `+1 …`, `0000000000` отклоняются |
| СНИЛС | цифры, пробелы и дефисы; ровно 11 цифр — хранятся только цифры. Показ и файл LMS — `XXX-XXX-XXX YY` |
| Серия и номер паспорта, индекс | пробелы убираются |
| Код подразделения | `NNNNNN`, `NNN-NNN`, `NNN - NNN` → `NNN-NNN` |

### Контрольное число СНИЛС

Методика ПФР. Номер — первые 9 цифр, контрольное число — последние 2. Для номеров до 001-001-998 включительно контрольное число не проверяется. Для остальных сумма произведений цифр номера на их позиции справа налево: первая цифра умножается на 9, девятая на 1. Сумма меньше 100 — это и есть контрольное число. Сумма 100 или 101 — контрольное число 00. Сумма больше 101 — берётся остаток от деления на 101, остаток 100 даёт 00.

### Сообщения

Ошибка называет поле и правило, значение не повторяет: «Контрольное число СНИЛС не совпадает с номером», «Код подразделения — 6 цифр в формате 000-000», «Дата выдачи паспорта должна быть позже даты рождения», «Значение длиннее 500 символов». Любая строка анкеты ограничена 500 символами. Методы `toString` у анкеты и оплаты не выводят ПДн, чтобы значения не попали в журнал при случайном логировании объекта.

## Файл «Загрузка пользователей» для LMS

`LmsRosterWorkbookWriter` формирует XLSX (Apache POI) из анкет потока.

| Что | Как |
|---|---|
| Лист1, строка 1 | 30 заголовков шаблона в том же порядке и написании |
| Строки | одна строка на зачисление потока в порядке ФИО. Одинаковый email у двух слушателей (родитель оплатил двоим детям) строку не убирает: диалог выгрузки предупреждает «LMS может не принять повтор» |
| Незаполненные обязательные поля | ячейка остаётся пустой; оператор до выгрузки выбирает «Выгрузить с пустыми ячейками» или «Исключить» (раздел «Раздел «Зачисление»») |
| Телефон | число `7XXXXXXXXXX`, как в образце; формат ячейки `0`, чтобы Excel не показывал экспоненту |
| Даты | ячейки даты с форматом `dd.mm.yyyy` (ДД.ММ.ГГГГ) |
| СНИЛС | текст `XXX-XXX-XXX YY` |
| Пустое поле | ячейка не создаётся |
| Текст, похожий на формулу | начинается с `=`, `+`, `-`, `@`, табуляции или возврата каретки — записывается с префиксом текста (quotePrefix), как в отчётах |
| Формат столбцов | СНИЛС, серия и номер паспорта, код подразделения, индекс и реквизиты диплома — текстовые (`@`), столбцы дат — формат даты. Если оператор дозаполнит файл в Excel, ведущие нули не потеряются |
| Лист2 | A1:A2 — «М», «Ж»; B1:B7 — справочник образования |
| Проверки данных | `L1:L1001` → `Лист2!$A$1:$A$2`, `W1:W1001` → `Лист2!$B$1:$B$7`, список со стрелкой, пустое значение допускается, ввод другого значения запрещён. При более чем 1000 строк диапазон продлевается до последней строки |

Отличия от файла организатора: проверки записаны стандартным элементом `dataValidations`, а не расширением x14 (ссылки на другой лист в стандартном элементе поддерживают Excel 2010+ и LibreOffice); email без гиперссылок `mailto`; ширина столбцов по длине заголовка.

Проверено: тест читает сформированный файл через POI обратно (заголовки, типы ячеек, Лист2, обе проверки данных), файл открыт в Excel 16 для Windows только для чтения (2 листа, проверка-список на L и W, телефон и даты показаны как в образце). В LibreOffice не проверялось: на машине разработки он не установлен.

## Загрузка заполненного шаблона

`LearnerWorkbookReader` читает файл, который оператор заполнил и загрузил обратно, и возвращает `LearnerWorkbook`: анкеты с протоколом ошибок по строкам и список заголовков, которые не удалось сопоставить, для предпросмотра. В БД ничего не пишется.

| Правило | Значение |
|---|---|
| Форматы | XLSX и XLS до 5 МиБ; распакованная часть XLSX до 12 МиБ на элемент архива, до 64 МиБ суммарно и не больше 200 частей архива; книга с паролем — ошибка файла |
| Настройки POI | лимиты распаковки `ZipSecureFile` общие на всю JVM. Читатель задаёт минимальную степень сжатия 0,01 и размер элемента 12 МиБ — те же значения, что `CatalogImportWorkbookReader`, поэтому порядок создания бинов не влияет на результат. Предел текста (`setMaxTextSize`) читатель не меняет: при 10 МиБ по умолчанию POI не пишет предупреждение, а файл до 5 МиБ в него укладывается. Суммарный лимит распаковки и число частей архива читатель проверяет сам ещё до вызова `WorkbookFactory.create`, потому что `ZipSecureFile` ограничивает только один элемент архива, а не архив целиком |
| Строка заголовков | ищется в первых 20 строках каждого листа по порядку. Подходит строка, где есть столбцы Фамилия, Имя и хотя бы один из столбцов Email или Номер телефона — по ним строка сопоставляется со слушателем |
| Сопоставление заголовков | заголовок шаблона или подпись поля (`LearnerField.label`: «Отчество», «Имя в дательном падеже», «Фамилия в дательном падеже», «Отчество в дательном падеже»). Сравнение без регистра, с «ё» = «е», только по буквам и цифрам. Поэтому «Отчество», «Отчество (при наличии)», «отчествопри наличии)» и заголовок шаблона совпадают, как и «Номер  телефона» с «Номер телефона» |
| Столбцы | до 60 заголовков в строке; отсутствующий необязательный столбец даёт пустое поле; повтор столбца (в том числе заголовок и подпись одного поля) — ошибка файла |
| Несопоставленные столбцы | значения не читаются, а непустые текстовые заголовки с повторными пробелами, сведёнными к одному, возвращаются в `ignoredHeaders`. Экран предпросмотра показывает их предупреждением уровня файла, чтобы опечатка в заголовке не теряла столбец молча |
| Строки | до 5000 непустых строк после заголовка; пустые пропускаются; номер строки в протоколе — номер строки Excel |
| Текст | число записывается без `.0`. Число с форматом даты в текстовом столбце — ошибка: «Excel сохранил значение как дату; введите его как текст» (например, дом «12/3») |
| СНИЛС, серия, номер паспорта, код подразделения, индекс числом | дополняются ведущими нулями до 11, 4, 6, 6 и 6 цифр с предупреждением «Восстановлены ведущие нули» у ячейки: формат General в шаблоне организатора теряет нули. Ошибочный СНИЛС ловит контрольное число |
| Телефон | число или строка, дальше общая нормализация |
| Дата | ячейка-дата Excel (число с форматом даты) или текст `ДД.ММ.ГГГГ` и `Д.М.ГГГГ` со строгой проверкой календаря: «31.02.2001» — ошибка. Число без формата даты — ошибка «Дата должна быть в формате ДД.ММ.ГГГГ»: иначе год рождения 2000, введённый числом, превратился бы в 22.06.1905 |
| Пол | «М» или «Ж» без учёта регистра |
| Образование | значение справочника без учёта регистра, повторных пробелов и вида тире (`-`, `–`, `—`) |
| Формула | берётся сохранённое значение; без сохранённого значения — ошибка ячейки; ошибка Excel в ячейке — ошибка ячейки |
| Дубли | читатель строки по email не отбрасывает: двое детей с почтой родителя — две разные строки. Дубль — две строки, сопоставленные с одним слушателем потока (раздел «Раздел «Зачисление»») |

Читатель возвращает значения строки, ошибки разбора ячеек и предупреждения, а также букву и заголовок каждого столбца. Правила полей применяет `QuestionnaireImportService` к анкете после слияния строки с текущей анкетой: пустая ячейка не стирает значение, поэтому правила вроде «паспорт целиком» и «выдан не раньше 14-летия» проверяются по итоговой анкете. Если ячейка не разобрана (формула без значения, неверная дата, значение не из справочника), правило для того же поля не добавляет второй ошибки. Ошибка файла возвращается одним сообщением и останавливает загрузку целиком; ошибки ячеек попадают в протокол строки и не мешают остальным строкам.

## Шифрование полей

`LearnerDataCipher` шифрует значения средствами JDK (`javax.crypto`).

| Параметр | Значение |
|---|---|
| Алгоритм | AES-256-GCM, тег 128 бит |
| IV | 12 случайных байт `SecureRandom` на каждое значение: одинаковые значения дают разные шифртексты |
| Формат хранения | `<версия>:<IV в Base64>:<шифртекст с тегом в Base64>`, например `v1:<16 символов>:<…>`. Версия — 1–16 строчных латинских букв и цифр |
| Контекст (AAD) | `encrypt(значение, контекст)` и `decrypt(хранимое, контекст)`. Дополнительные данные GCM — UTF-8 строки `<версия>:<контекст>`. Поле анкеты шифруется `encryptField(id слушателя, поле, значение)` с контекстом `learner:<id слушателя>:<код поля>`, например `learner:<id>:SNILS`, поэтому AAD содержит версию ключа, идентификатор слушателя и код поля (версия ключа, идентификатор слушателя и код поля). Идентификатор слушателя создаётся в приложении до первого шифрования. Пустой контекст — ошибка «Не задан контекст зашифрованного значения». Контекст в хранимое значение не пишется: его восстанавливают из строки и столбца БД |
| Подмена | изменённый шифртекст, чужой IV или ключ, значение, перенесённое в другую анкету или другое поле, и замена префикса версии дают ошибку «Зашифрованное значение повреждено или не соответствует ключу» |
| Сообщения | открытые значения и ключи в исключения и журналы не попадают |

Флаг модуля — `app.modules.enrolment.enabled` (`ModuleProperties`), переменная `MODULE_ENROLMENT_ENABLED`, по умолчанию `false`; другие флаги модулей и порядок включения — в `docs/deploy.md`, раздел «Модули». Настройки ключей `app.enrolment` (`EnrolmentProperties`), значения только из переменных окружения:

| Свойство | Переменная | По умолчанию |
|---|---|---|
| `active-key-version` | `APP_ENROLMENT_ACTIVE_KEY_VERSION` | пусто |
| `keys.v1`, `keys.v2`, … | `APP_ENROLMENT_KEYS_V1`, `APP_ENROLMENT_KEYS_V2`, … | пусто |
| `fingerprint-key` | `APP_ENROLMENT_FINGERPRINT_KEY` | пусто |

Ключ шифрования — ровно 32 байта в Base64 (обычном или URL-safe, с выравниванием `=` или без). Ключ отпечатков — не меньше 32 байт. Если модуль выключен, ключи не проверяются, а любой вызов шифрования завершается ошибкой «Модуль «Слушатели» выключен». Если модуль включён, а ключа активной версии или ключа отпечатков нет или он неверной длины, приложение не запускается; сообщение называет переменную, но не значение. Приложение не запускается и тогда, когда ключ отпечатков совпадает с любым ключом шифрования (сравнение байтов через `MessageDigest.isEqual`): «Ключ отпечатков APP_ENROLMENT_FINGERPRINT_KEY совпадает с ключом шифрования APP_ENROLMENT_KEYS_V1; задайте отдельный ключ».

В файле `.env.local` для compose параметры ключей называются `ENROLMENT_ACTIVE_KEY_VERSION`, `ENROLMENT_KEYS_V1`, `ENROLMENT_KEYS_V2`, `ENROLMENT_FINGERPRINT_KEY` — по тому же правилу, что `SITE_TOKEN` → `APP_SOURCES_WEBSITE_TOKEN`: `.env.local` читает compose, а backend видит только переменные, перечисленные в `environment` сервиса. `compose.yaml` передаёт их в контейнер backend (`APP_ENROLMENT_ACTIVE_KEY_VERSION: ${ENROLMENT_ACTIVE_KEY_VERSION:-}` и так же для остальных, пустые значения по умолчанию) и отдельным блоком флаги модулей `MODULE_ENROLMENT_ENABLED` и `MODULE_PARTNER_ENABLED` (по умолчанию `false`); `compose.prod.yaml` и `compose.edge.yaml` окружение backend дополняют и эти переменные не переопределяют. `backend-bootstrap` ключей не получает: демо-bootstrap анкет не создаёт.

`scripts/bootstrap-demo.sh` и `.ps1` при пустых значениях генерируют `ENROLMENT_KEYS_V1` и `ENROLMENT_FINGERPRINT_KEY` из 32 случайных байт (Base64 URL-safe без `=`, 43 символа — формат, который принимает `LearnerDataCipher`), как остальные секреты, ставят `ENROLMENT_ACTIVE_KEY_VERSION=v1` и включают модуль на демо-стенде: `MODULE_ENROLMENT_ENABLED=true` при `DEMO_DATA=true`, `false` при установке без демо-данных. Значения, уже записанные в `.env.local`, скрипт не меняет, но дописывает отсутствующие: на стенде, где строки ещё нет, при выкладке она появится; прежнее имя `ENROLMENT_ENABLED` скрипт переносит в `MODULE_ENROLMENT_ENABLED`, если новой строки нет. Чтобы включить или выключить модуль, правят строку `MODULE_ENROLMENT_ENABLED` и запускают скрипт заново.

| Где | Имя |
|---|---|
| `.env.local`, `.env.example`, bootstrap-скрипты | `MODULE_ENROLMENT_ENABLED`, `ENROLMENT_ACTIVE_KEY_VERSION`, `ENROLMENT_KEYS_V1`, `ENROLMENT_KEYS_V2` (для ротации), `ENROLMENT_FINGERPRINT_KEY` |
| окружение контейнера backend, сообщения при старте | `MODULE_ENROLMENT_ENABLED`, `APP_ENROLMENT_ACTIVE_KEY_VERSION`, `APP_ENROLMENT_KEYS_V1`, `APP_ENROLMENT_KEYS_V2`, `APP_ENROLMENT_FINGERPRINT_KEY` |
| `application.yml` | `app.modules.enrolment.enabled`, `app.enrolment.active-key-version`, `keys.v1`, `fingerprint-key` |

### Ротация ключа

1. Сгенерировать новый ключ, например `openssl rand -base64 32`, и сохранить его там же, где остальные секреты развёртывания.
2. Записать ключ в `ENROLMENT_KEYS_V2` в `.env.local`, не удаляя `ENROLMENT_KEYS_V1`, задать `ENROLMENT_ACTIVE_KEY_VERSION=v2` и перезапустить backend (`docker compose up -d backend`). Новые и изменённые анкеты шифруются версией `v2`, старые читаются ключом `v1`. Переменная `APP_ENROLMENT_KEYS_V2` попадает в `app.enrolment.keys.v2` без правки `application.yml`: это проверяет тест. Для третьей и следующих ротаций строку `APP_ENROLMENT_KEYS_V3: ${ENROLMENT_KEYS_V3:-}` нужно добавить в `compose.yaml`.
3. Задание `LearnerRekeyJob` запускается через минуту после старта backend и затем каждый час. Оно выбирает анкеты, у которых `learners.key_version` не равна активной версии, порциями по 100 в порядке идентификатора и перешифровывает каждую в своей транзакции под блокировкой строки: все значения расшифровываются старым ключом и заново шифруются активным, отпечатки пересчитываются, `version` анкеты не меняется, поэтому открытая у оператора правка не получает `409`. Обезличенные анкеты не затрагиваются. Анкету, которую не удалось расшифровать (нет ключа её версии, значение повреждено), задание пропускает и пишет в журнал backend её идентификатор и причину без значений; остальные перешифровываются. Итог прохода — строка журнала backend с числом перешифрованных и пропущенных анкет. Число анкет со старой версией ключа видно администратору в блоке «Сроки хранения».
4. Когда анкет старой версии не осталось (счётчик — 0), удалить `ENROLMENT_KEYS_V1`. Если ключ удалить раньше, значения этой версии не читаются: «Нет ключа шифрования версии «v1»».

Смена ключа отпечатков выполняется вместе с ротацией ключа шифрования: новый `ENROLMENT_FINGERPRINT_KEY` задаётся в том же перезапуске, и задание пересчитывает отпечатки каждой перешифрованной анкеты. Пока задание не закончило проход, поиск и дедупликация не находят анкеты с прежними отпечатками, поэтому загрузку оплат и заполненных шаблонов на это время не выполнять.

Ключи не входят в резервную копию БД и хранятся отдельно от неё: копия без ключа бесполезна, копия вместе с ключом раскрывает данные.

### Отпечатки для поиска и дедупликации

Отпечаток — HMAC-SHA256 на ключе отпечатков от строки `<вид>:<нормализованное значение>`, 64 шестнадцатеричных символа. Вид в начале строки разводит одинаковые строки разных видов. Отпечатки позволяют искать и находить дубли без расшифровки: запрос выбирает кандидатов по отпечатку, и расшифровываются только они. Поиск точный, варианты написания не применяются. У ключа отпечатков нет версий: его смена требует пересчитать отпечатки всех анкет из расшифрованных значений (раздел «Ротация ключа»).

| Вид | Столбец | Нормализация | Для чего |
|---|---|---|---|
| `email` | `email_hmac` | края, нижний регистр | дедупликация при загрузке оплат, поиск, сопоставление строк шаблона |
| `phone` | `phone_hmac` | `+7XXXXXXXXXX`; телефон, который не приводится к формату, отпечатка не получает | то же |
| `snils` | `snils_hmac` | 11 цифр | один СНИЛС — одна анкета (уникальный индекс), поиск |
| `name` | `name_hmac` | фамилия и имя через пробел, без отчества, нижний регистр, «ё» → «е», повторные пробелы убраны | поиск субъекта ПДн по фамилии и имени: отчество в оплате необязательно |
| `last_name` | `last_name_hmac` | фамилия, нижний регистр, «ё» → «е» | поиск оператора по фамилии |

Ограничение: пространство телефонов и СНИЛС мало, поэтому при одновременной утечке БД и ключа отпечатков значения восстанавливаются перебором. Поэтому ключ отпечатков отдельный и хранится отдельно от БД.

## Хранение анкет

Миграция V28 создаёт три таблицы; журнал — существующая `audit_events` (V21).

| Таблица | Содержимое |
|---|---|
| `enrolment_streams` | поток = курс + номер внутри курса: ключ курса `course_key` (как у PROGRAM-сопоставления, `name:…`), название курса, `stream_no`, дата окончания `ends_on`, `version`; уникальность (`course_key`, `stream_no`) |
| `learners` | анкета: `fields` — объект JSON «код поля → зашифрованное значение», пустые поля в объекте отсутствуют; `key_version` — версия ключа всех значений строки; пять отпечатков; `missing_fields` — коды незаполненных полей через запятую, без значений (полнота анкеты и обязательные поля считаются без расшифровки); `personal_data_status` — `ACTIVE`, `RESTRICTED` или `ANONYMIZED`; `anonymized_at`; `version`; `created_by` (NULL — слушатель создан служебным актором «Система») |
| `learner_enrolments` | зачисление: слушатель, поток, запись `paid_order` в `source_records` (уникальна), идентификатор и время выгрузки, время передачи в LMS; один слушатель — одно зачисление в потоке |

Ограничение `learners_profile_state` не даёт обезличенной строке хранить документ, версию ключа или отпечатки, а необезличенной — остаться без них. `fields` имеет тип `TEXT`, а не `JSONB` из наброска п. 11.3: внутри значения зашифрованы, искать и индексировать в JSON нечего, остальные JSON-столбцы проекта тоже `TEXT`, а тесты на H2 `JSONB` не поддерживают.

При каждом сохранении (`LearnerService.create`, `update`) анкета нормализуется и шифруется целиком активным ключом: `key_version` одна на строку, поэтому число анкет со старой версией считается по этому столбцу. Правка идёт с `version` (`409 VERSION_CONFLICT`) и под блокировкой строки; СНИЛС, который уже есть у другого слушателя, — ошибка поля `SNILS` «СНИЛС уже есть у другого слушателя» (проверка перед записью и уникальный индекс). Обезличенная анкета не меняется (`409 PERSONAL_DATA_ANONYMIZED`), анкета с ограниченной обработкой — тоже (`409 PERSONAL_DATA_RESTRICTED`, снимает ограничение администратор). Поиск без расшифровки таблицы: `findByContacts` (email или телефон), `findBySnils`, `findByLastName`; до 200 кандидатов, расшифровываются только они.

## Журнал и маскирование

Журнал — таблица `audit_events`, категория `LEARNER` (раздел «Слушатели» в «Журнале администратора и безопасности»). Тип объекта — `LEARNER`, в `object_name` вместо ФИО — «Слушатель» и первые 8 знаков идентификатора; в подробностях — коды полей и групп, без значений ПДн.

| Действие | Когда | Состояние |
|---|---|---|
| `LEARNER_VIEWED` | открыта анкета (`LearnerService.card`) | пишется |
| `LEARNER_FIELDS_REVEALED` | «Показать» у групп (`reveal`), подробности «группы: DOCUMENTS, PERSONAL» | пишется |
| `LEARNER_CHANGED` | сохранена изменённая анкета (`update`), подробности «поля: PHONE, SNILS» | пишется |
| `LEARNER_SEARCHED` | поиск оператора: «вид: EMAIL; найдено: 1», значение не пишется; тип объекта `LEARNER` без идентификатора | пишется |
| `LEARNER_ENROLMENTS_MOVED` | перенос зачислений к слушателю с тем же СНИЛС: у найденного слушателя, в подробностях — идентификатор удалённой анкеты, число перенесённых и удалённых зачислений, коды перенесённых полей | пишется |
| `LEARNER_LIST_VIEWED`, `LEARNER_TEMPLATE_PREVIEWED`, `LEARNER_TEMPLATE_IMPORTED`, `LMS_ROSTER_EXPORTED`, `LMS_ROSTER_MARKED`, `STREAM_END_DATE_CHANGED` | процессы потока: тип объекта `STREAM`, имя «курс, поток N», в подробностях — числа, режим и идентификатор выгрузки | пишется |
| `PAID_ORDERS_UPLOADED`, `LEARNERS_SYNCED` | приём оплат в модуль (раздел «Приём оплат в модуль») | пишется |
| `SUBJECT_SEARCHED`, `SUBJECT_EXPORTED`, `SUBJECT_ANONYMIZED`, `LEARNER_RESTRICTED`, `LEARNER_RESTRICTION_LIFTED` (категория «Действия с ПДн») | функции субъекта ПДн у администратора: по событию на каждого найденного или изменённого слушателя | пишется |
| `RETENTION_APPLIED` (категория «Сроки хранения») | ночная задача: «обезличено анкет слушателей: N» | пишется |

Маскирование — `LearnerFieldGroup`, группы экрана «Анкета»:

| Группа | Поля | В анкете |
|---|---|---|
| `MAIN` «Основное» | ФИО, телефон, email | ФИО полностью; телефон `+7 9** ***-**-34`; email `i***@example.test` |
| `DOCUMENTS` «Документы» | СНИЛС и паспорт | СНИЛС `***-***-*** 12`, номер паспорта `****56`, остальные поля `***` |
| `PERSONAL` «Личные сведения» | пол, дата рождения | `***` |
| `ADDRESS` «Адрес» | адрес регистрации | `***` |
| `DATIVE` «Дательный падеж» | ФИО в дательном падеже | полностью |
| `EDUCATION` «Образование» | образование и диплом | `***` |

`LearnerService.card` возвращает анкету с масками (пустых полей в ней нет), перечень незаполненных полей и зачисления и пишет `LEARNER_VIEWED`. `reveal` возвращает значения выбранных групп (даты — `ГГГГ-ММ-ДД`, пол и образование — в написании шаблона) и пишет `LEARNER_FIELDS_REVEALED`. Анкета с ограниченной обработкой (`409 PERSONAL_DATA_RESTRICTED`) и обезличенная (`409 PERSONAL_DATA_ANONYMIZED`) не раскрываются. Ответы с раскрытыми значениями отдаёт с `Cache-Control: no-store`. `toString` анкеты и раскрытых сведений значений не выводит; сообщения шифрования и перешифрования называют идентификатор анкеты, но не значение.

## Раздел «Зачисление»

API — `/api/enrolment` (`EnrolmentApiController`, `openapi.yaml`, тег Enrolment), экран — `frontend/src/features/enrolment`. Каждый метод сначала вызывает `EnrolmentAccess.requireOperator` по свежему профилю: модуль выключен — `404` всем, включён — только USER или LEADER с флагом «Оператор зачисления», остальным `403`, в том числе ADMIN. Проверка идёт до поиска объекта, поэтому без флага и чужой, и несуществующий идентификатор дают одинаковый `403`.

| Метод | Что делает |
|---|---|
| `GET /streams` | потоки: курс, номер, программа (по сопоставлению курса), «Оплачено» — зачисления потока (одно на слушателя), «Анкеты» — полные анкеты, «Выгружено», «Передано», «Ожидает» — без отметки «передано», дата окончания, «Хранить до» = окончание + срок хранения; счётчики анкет и потоков без даты окончания |
| `PATCH /streams/{id}` | дата окончания потока с `version` и `Idempotency-Key`, `STREAM_END_DATE_CHANGED` |
| `GET /streams/{id}/learners` | весь поток одним ответом с сортировкой по ФИО в приложении: ФИО, маски телефона и email, номер заявки, полнота, отсутствующие для LMS поля, повтор email, статус LMS; выгрузки потока; сводка для диалога выгрузки по режимам (строк, без обязательных полей, повтор email, недоступно); `LEARNER_LIST_VIEWED` |
| `POST /learners/search` | точный поиск по email, телефону, СНИЛС или фамилии через отпечатки, значение — в теле запроса |
| `GET /learners/{id}` | анкета с масками и зачислениями, `LEARNER_VIEWED` |
| `POST /learners/{id}/reveal` | значения групп, `LEARNER_FIELDS_REVEALED`; экран открывает форму правки группы только после раскрытия |
| `PATCH /learners/{id}` | только изменяемые поля (пустое значение очищает поле) с `version`; правила полей по итоговой анкете, ошибки — `fieldErrors` по кодам полей; СНИЛС другого слушателя — ошибка поля `SNILS`, после которой экран предлагает перенос |
| `POST /learners/{id}/move-enrolments` | перенос зачислений открытой анкеты к слушателю с указанным СНИЛС одной транзакцией: зачисления в потоках, где он уже зачислен, удаляются (заявки остаются в спросе), его пустые поля получают значения открытой анкеты, открытая анкета удаляется |
| `GET /learners/{id}/history` | события журнала по анкете без значений, новые сначала |
| `POST /streams/{id}/questionnaire-imports/preview`, `.../apply` | заполненный шаблон: антивирус ClamAV, строка сопоставляется только со слушателями потока — кандидаты по отпечатку email или телефона, из них с теми же фамилией и именем (отчество — если есть в обоих); нет кандидатов — «Слушателя нет в потоке», ФИО не совпадает или совпадает у нескольких — «Конфликт», вторая строка того же слушателя — ошибка со ссылкой на первую, анкета с ограниченной обработкой — «Конфликт». Отпечаток предпросмотра — SHA-256 файла, потока и версий всех анкет потока; применение с тем же файлом и отпечатком, иначе `409 VERSION_CONFLICT` и новый предпросмотр |
| `POST /streams/{id}/lms-roster` | файл для LMS: режим «Только не переданные» или «Все слушатели потока», анкеты без Фамилии, Имени, телефона или email — с пустыми ячейками или исключить; анкеты с ограниченной обработкой и обезличенные не выгружаются. Не переданным зачислениям файла ставится идентификатор выгрузки (`X-Roster-Export-Id`); уже переданные сохраняют свою отметку. Имя файла `LMS_<курс>_поток<N>_<дата>.xlsx`, `no-store`, `LMS_ROSTER_EXPORTED` |
| `POST /roster-exports/{id}/transferred` | отметка «передано» ровно по зачислениям выгрузки, ещё не отмеченным; `marked = 0` — неотмеченных нет |

Ответы с ФИО и значениями (слушатели потока, поиск, анкета, раскрытие, предпросмотр, файл) идут с `Cache-Control: no-store`. Изменяющие методы принимают `Idempotency-Key` (кроме файла для LMS: файл с анкетами для повтора не сохраняется). Отпечаток запроса команд со значениями ПДн (правка анкеты, перенос по СНИЛС) — HMAC на ключе отпечатков, а не открытый SHA-256: иначе по отпечатку и известным полям перебором восстанавливался бы СНИЛС. Сохранённые для повтора итоги значений не содержат: правка хранит только идентификатор анкеты, заполненный шаблон — строки без ФИО.

## Функции субъекта ПДн

Администратор видит сведения о слушателе только через функции субъекта ПДн по обращению субъекта; экрана анкет и файла для LMS у него нет.

- Поиск (`POST /api/admin/personal-data/search`) находит слушателя только по точному совпадению нормализованных email, телефона (`+7XXXXXXXXXX`), СНИЛС (поле `snils`, ищется только среди анкет) или фамилии и имени — первых двух слов поля «ФИО» в любом порядке, отчество не учитывается — через отпечатки. Варианты написания к анкетам не применяются. Результат `learners`: идентификатор, состояние, число заполненных полей, потоки; значений анкеты в нём нет. При выключенном модуле слушатели не ищутся, неверный СНИЛС — ошибка поля `snils`.
- Выгрузка сведений (`/export`) содержит расшифрованную анкету каждого найденного слушателя (поле и значение, даты `ДД.ММ.ГГГГ`) и его потоки: в JSON — `learnerProfiles`, в PDF — раздел «7. Анкеты слушателей». Цели, источники и получатели в выгрузке дополнены слушателями.
- Ограничение обработки (`POST /api/admin/personal-data/learners/{id}/restriction`, `version`, `Idempotency-Key`) ставит статус `RESTRICTED`: анкета хранится и учитывается в статистике, но оператор зачисления её не раскрывает и не изменяет, пока ограничение не снято.
- Обезличивание (`POST /api/admin/personal-data/anonymization`, поле `learnerIds`) удаляет поля анкеты и отпечатки, статус `ANONYMIZED`; зачисления и оплаченные заявки остаются. Файлы заказанных отчётов при этом не удаляются: данных анкет в отчётах нет.
- Уточнение данных по обращению субъекта выполняет оператор зачисления в анкете.
- Каждый шаг пишется в журнал: общее событие `SUBJECT_*` с числом найденного и по событию с типом объекта `LEARNER` на каждого слушателя; условия поиска в журнал не попадают.

## Срок хранения анкет

Ночная задача сроков хранения (`RetentionService`, расписание `RETENTION_CRON`) обезличивает анкеты по политике `app.retention.learner-profiles`: переменная backend `APP_RETENTION_LEARNER_PROFILES`, в `.env.local` — `RETENTION_LEARNER_PROFILES`, по умолчанию `P3Y` — 3 года после окончания потока (значение по умолчанию до решения оператора ПДн). Значение — период ISO-8601 (`P3Y`, `P2Y6M`, `P30D`): поле `learnerProfiles` в `RetentionProperties` имеет тип `java.time.Period`, потому что `Duration` не принимает годы.

- Срок считается календарно по московской дате: «хранить до» = `ends_on.plus(срок)`. Для потока, закончившегося 01.09.2023, это 01.09.2026; анкета обезличивается, когда эта дата прошла, то есть при запуске 02.09.2026 и позже.
- Слушатель обезличивается, когда «хранить до» прошла у всех его зачислений: документ анкеты, версия ключа и отпечатки удаляются, статус `ANONYMIZED`, `anonymized_at` — время запуска. Зачисления, потоки и записи `paid_order` остаются, поэтому число оплат, потоков и зачислений в статистике не меняется. Анкета с ограниченной обработкой обезличивается так же. Ключи для этого не нужны: задача работает и при выключенном модуле.
- Слушатель с зачислением в потоке без даты окончания не обезличивается. Число таких потоков администратор видит в блоке «Сроки хранения» с предупреждением, что срок хранения анкет не определён; оператор зачисления — в списке потоков.
- Число обезличенных анкет — в итоге запуска и в событии `RETENTION_APPLIED` («обезличено анкет слушателей: N»); отдельного события на каждую анкету нет.
- Обезличивание раньше срока — функция администратора по обращению субъекта (раздел «Функции субъекта ПДн»).
- Пока модуль выключен, анкеты по сроку не обезличиваются и ротация ключа не выполняется: задачи модуля не запускаются, данные остаются в базе. Включение возвращает их в работу, просроченные анкеты обезличиваются при ближайшем запуске.

Блок «Сроки хранения» у администратора (`GET /api/admin/retention`, поле `learners`): срок анкет, число анкет в CRM (не обезличенных), порог 100 000 субъектов — условие уровня защищённости УЗ-4 (п. 12 «б» ПП № 1119, `docs/delivery/security/2_Уровень_защищённости.md`), предупреждение с 80 000 анкет, число потоков без даты окончания, число анкет со старой версией ключа (при выключенном модуле — «модуль выключен»). При 80 000 анкет и больше ночная задача пишет предупреждение и в журнал backend.

## Выключенный модуль

Модуль включается флагом `MODULE_ENROLMENT_ENABLED` (по умолчанию выключен, на демо-стенде включён). При выключенном модуле:

- все методы `/api/enrolment/**` и `POST /api/admin/personal-data/learners/{id}/restriction` отвечают `404` (не `403`), независимо от роли и флага;
- раздела «Зачисление» нет, флаг «Оператор зачисления» нельзя поставить (`PATCH /api/admin/crm-profiles/{id}` с `enrolmentOperator: true` — `400`), он скрыт в профилях и справке;
- в отчёте «Востребованность программ» нет колонок и сортировки по оплатам: запрос с ними не отклоняется, колонки отбрасываются, сортировка по оплатам заменяется сортировкой по заявкам;
- синхронизация сайта оплаты не принимает, ключ анкет не меняется, анкеты по сроку не обезличиваются;
- в «Субъекте персональных данных» слушатели не ищутся, в «Сроках хранения» нет блока анкет, в журнале нет раздела «Слушатели»;
- данные в базе не удаляются: повторное включение возвращает всё как было.

Файл «Загрузка пользователей» для преподавателей вуза (повышение квалификации) от модуля не зависит.
